## How the agents work
`common.py` is a small tool-calling loop over the router's OpenAI-compatible chat API (`OSO_ROUTER_BASE_URL`, default the dev mock). The model never sees a platform key: tools run in the harness with the agent's own key, through `SdkBackend` or `McpBackend`. Retrieved context goes to the model inside `<retrieved_context>` as quoted data.

**Offline the model is scripted.** The mock router plays it from rules generated by `scripted_rules` (one rule per turn), so the transcript is reproducible and strict mode catches drift; only the platform side is real. With `--live` (owner action, costs money) a real model chooses the calls. Never treat the offline answers as evidence about a model.

## Use it from Claude Code or Claude Desktop
Register an agent (see `docs/runbooks/agent-onboarding.md`), then copy [mcp/claude-code.mcp.json](mcp/claude-code.mcp.json) into your project (`KG_AGENT_KEY` in the environment) or [mcp/claude-desktop.json](mcp/claude-desktop.json) into Claude Desktop's config. MCP is a transport over the same authorised API: the server holds no credential and forwards the caller's key, so an agent sees exactly what it would see over HTTP.

## Notes from building it
- The profile check answers `422 profile_not_allowed` (SDK `ValidationError`), not 403.
- A per-principal request quota surfaces as `QuotaExceeded` (429 `quota_exceeded`), not `RateLimited`.
- Evidence for a proposal must be an interaction the proposing agent can read; the Research agent stores its source page itself before citing it.
