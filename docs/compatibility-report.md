## Findings and decisions by check

### GR-01 — Graphiti installs and builds indices on Neo4j 5.26
*PASS · OFFLINE*

Graphiti 0.30.2 builds its range + fulltext indexes on Neo4j 5.26 Community (index types seen: FULLTEXT, LOOKUP, RANGE). The Neo4j driver also schedules build_indices_and_constraints() itself at construction, so an explicit call races it and logs harmless 'equivalent index already exists' errors. APOC is present in the spike image; Graphiti 0.30.2 core paths used here ran without needing it.

### GR-02 — Graphiti LLM client wire format vs router (chat completions only, stripped fields)
*PASS · OFFLINE*

OpenAIGenericClient posts only to /v1/chat/completions with {model,messages,temperature,max_tokens,response_format}; all are kept by the router's zod schema. response_format is json_schema WITHOUT strict. The embedder posts /v1/embeddings (the SDK adds encoding_format, which the router strips). Result: the generic client is router-compatible as is. Graphiti's default OpenAIClient calls /v1/responses -> 404 on the router. Decision: always construct OpenAIGenericClient (json_schema mode). Wrap it in an adapter that keeps this invariant under test.

### GR-03 — Runtime ontology compiler: Pydantic types accepted; reserved-name collisions
*PASS · OFFLINE*

PASS with one required adaptation. create_model() builds types at runtime and Graphiti accepts them. The blueprint's own example ontology (Person.attributes.name) COLLIDES with the reserved EntityNode field 'name' and Graphiti raises EntityTypeValidationError. Compiler rule: 'name' is the node's own name, so it is not emitted (kept as the platform identity alias); any other reserved collision is a compile error for the author. All compiled fields are Optional so one missing attribute cannot fail an extraction; 'required' is enforced by the platform validator. Type/edge names are checked against ^[A-Za-z][A-Za-z0-9_]{0,63}$ and Graphiti's reserved labels/edges. The allowlisted-static-class fallback is NOT needed.

### GR-04 — group_id namespacing: isolation, traps, charset, DB-per-tenant
*PASS · OFFLINE*

Shared database + group_id property is the only option on Neo4j Community (CREATE DATABASE is unsupported; the driver's clone() is a no-op so group_id never selects a database). Isolation holds ONLY if every call passes group_ids: search() with group_ids=None, get_by_uuid and group_id=None (-> '') are NOT scoped. ADR-015: the graph adapter (packages/graph) must derive group_id from the authenticated workspace, refuse None/empty, always pass group_ids, and re-check group_id after any by-uuid fetch. Recommended mapping group_id = 'ws-<workspace uuid>'. Database-per-tenant needs Neo4j Enterprise (decision deferred to production: record in ADR-015).

### GR-05 — Deterministic writes with zero LLM calls
*PASS · OFFLINE*

EntityEdge.created_at is a REQUIRED constructor field (no default), so the caller always chooses the record time. Deterministic path = graphiti.nodes.entity.save + graphiti.edges.entity.save: ZERO chat calls (only embeddings, which a command write needs for search anyway). add_triplet is NOT LLM-free: it dedupes/contradiction-checks via the LLM whenever an edge between the nodes already exists (and for node resolution). Decision (ADR-016): P2 writes trusted commands with direct save through a platform projection writer that sets uuid/valid_at/created_at itself; it never calls add_triplet/add_episode. Supersession for commands is done by the writer (set invalid_at/expired_at on the previous edge), not by Graphiti. Quirk: an edge read back carries source_uuid/target_uuid inside .attributes; the projection reader must strip them before comparing attributes.

### GR-06 — Temporal field mapping (valid/invalid/created/expired)
*PASS · OFFLINE*

Valid time maps cleanly: valid_at/invalid_at, and a backdated successor invalidates its predecessor at its own valid_at. RECORD time does not: add_episode stamps created_at/expired_at with wall-clock now, so evt_002 'recorded 2024-06-10' would read as today. Mitigation (ADR-017): the platform's Postgres fact table is the system of record for recorded_at/superseded_at and as_of/known_at; the graph projection carries valid_from/valid_to and, where cheap, overwrites created_at with the ledger's recorded_at after add_episode (shown to work). Formal bitemporal SLA stays out of MVP scope (DEC-12).

### GR-07 — Correcting edges: invalidate / edit / delete
*PASS · OFFLINE*

All three operations work through the namespace API. Caveats: (a) invalidated edges are NOT excluded from search unless the caller passes an expired_at IS NULL filter (and valid-time filters for as_of); (b) in-place edit loses the original text, keeps provenance, and records nothing about who/why; (c) delete leaves the edge uuid inside EpisodicNode.entity_edges. DECISION (ADR-018, DEC-04): corrections are authoritative in a Postgres fact-status projection (rejected/disputed/superseded/deleted) that every read path joins/filters on; the graph edge is updated best-effort (expired_at + invalid_at, or delete) and every graph search carries the expired_at filter. Never rely on in-place edits as the audit trail.

### GR-08 — Deleting episodes and derivatives; orphans; group purge
*PASS · OFFLINE*

remove_episode deletes: the Episodic node, edges whose FIRST episode is the removed one, and entities mentioned by no other episode. It does NOT: rewrite summaries/attributes on surviving entities (derived text survives), prune the removed episode uuid from other edges' .episodes (dangling refs), or protect an edge that a later episode also supports when the owner is removed. Orphan entities created outside episodes are never cleaned (platform Cypher drafted). clear_data(driver, [group]) purges one tenant cleanly. P8 deletion therefore = remove_episode for each source episode + re-summarise or delete surviving entities that cite the subject + prune dangling refs + orphan sweep + verification query, not remove_episode alone.

### GR-09 — Idempotency of re-adding an episode
*PASS · OFFLINE*

Graphiti does NOT deduplicate episodes by name or content: re-adding creates a second Episodic node (entities and the identical-fact edge are deduplicated, but the edge's .episodes list grows). Re-adding with the SAME explicit uuid is idempotent (one Episodic node) - BUT add_episode(uuid=...) only CONTINUES an episode that already exists (NodeNotFoundError otherwise), so the worker must first save an EpisodicNode with the deterministic uuid (graphiti.nodes.episode.save) and then call add_episode(uuid=...). Decision (confirms ING-01): idempotency lives in the platform ledger keyed (workspace, source_key, stage); the worker derives uuid5(namespace, ledger key) so a retry reuses the same episode, and records the Graphiti episode uuid in the ledger before marking the stage done. A repeat add still costs LLM calls (see chat_calls_second), so the ledger must prevent needless replays rather than rely on Graphiti.

### GR-10 — Search recipes without a cross-encoder
*PASS · OFFLINE*

Chosen recipes: facts = EDGE_HYBRID_SEARCH_RRF (default) or EDGE_HYBRID_SEARCH_NODE_DISTANCE with center_node_uuid for subject-centred retrieval; nodes = NODE_HYBRID_SEARCH_RRF; MMR variants also work. None call the cross-encoder. Graphiti.search_() DEFAULTS to the CROSS_ENCODER recipe, so the adapter must always pass an explicit config; a NoCrossEncoder that raises is installed so any accidental use fails loudly (the router drops logprobs, so OpenAIRerankerClient cannot work). Graphiti.search() mutates the shared recipe's .limit; the adapter should copy the recipe (config.model_copy()) per call. Retrieval QUALITY with E5-small is measured live (LV-05/GR-11); offline vectors are lexical hashes and only prove plumbing and group scope. MMR uses sim_min_score=0.6 (tuned for other embedding models); E5-family cosine similarities are generally reported to cluster high, so thresholds must be re-tuned from live data (LV-05 records related vs unrelated cosine).

### GR-13 — Concurrency / SEMAPHORE_LIMIT under router rate limits
*PASS · LIVE*

Largest parallelism with no 429 on oso/fast: 16. Recommended Graphiti SEMAPHORE_LIMIT = 8 (half, for headroom), plus a client-side token bucket under the key's RPM/TPM and Retry-After honoured by the ModelGateway.

### PV-01 — Exact scoped vector search with SQL prefilter (50k rows)
*PASS · OFFLINE*

Exact cosine search with workspace/scope/status predicates IN the SQL returned the brute-force top-10 for all 200 random scoped queries and never left scope. Baseline on 50k rows: p50 9.0 ms, p95 63.2 ms (btree on (workspace_id, scope_kind, status) narrows to ~1/100 of rows, then an exact sort). Confirms exact scoped search as the MVP default (DEC-08).

### PV-02 — Row-level security incl. vector search
*PASS · OFFLINE*

RLS (ENABLE + FORCE, policy on workspace_id = current_setting('app.workspace_id', true)) isolates workspaces even for an UNFILTERED ORDER BY embedding <=> q query and for known foreign ids; cross-workspace INSERT/UPDATE are blocked; with the setting absent the result is empty (fail-closed). Control: the spike's owner role is a SUPERUSER and still sees all 50,000 rows, because superusers and BYPASSRLS roles ignore RLS even with FORCE. SET LOCAL (set_config(..., true)) does not outlive a REAL transaction. PITFALL found while writing this test: on a psycopg connection in non-autocommit mode, `with conn.transaction()` is only a SAVEPOINT inside the implicit outer transaction, so the workspace setting survived into the next block and a 'no workspace set' query saw the previous tenant's 2,442 rows. P1 must open request transactions explicitly (autocommit=True + conn.transaction(), or SQLAlchemy begin()) and include a test that a second request on a reused pooled connection sees nothing until it sets its own workspace. REQUIREMENTS for P1: the app connects as a NON-superuser, NOBYPASSRLS role; every request runs in a transaction that sets app.workspace_id from the authenticated principal; RLS is defence in depth, SQL predicates (PV-01) remain the primary scope mechanism because scope/ACL logic is richer than workspace.

### PV-03 — HNSW iterative scan vs exact: recall under selective filters
*PASS · OFFLINE*

Under a selective filter (1 workspace + 1 scope, ~450 of 50k rows) plain HNSW post-filters its ef_search candidates and returns far fewer true neighbours: mean recall@10 0.038 at ef_search=40; iterative scan (pgvector 0.8.x) recovers 0.703 (strict_order) but is still approximate and slower than the exact scoped sort (p50 1.65 ms). Decision (ADR-019 / DEC-08): MVP uses EXACT scoped search (btree-narrowed sort); ANN is deferred until a per-workspace evaluation shows size/latency need, and then only with iterative_scan on and recall re-measured per workspace. The planner with both indexes present: see planner_choice_with_both_indexes.

### PV-04 — Embedding version columns and re-embed path
*PASS · OFFLINE*

Every vector row carries embedding_model_id, embedding_dim and embedding_version, with CHECK (vector_dims(embedding) = embedding_dim); a wrong-sized insert fails. Re-embed paths. (A) SAME dimension, new model: write new vectors with embedding_version = N+1 in batches (worker, resumable via the ledger), keep reads pinned to `embedding_version = <current>` from config, flip the config value when coverage is 100%, then delete old versions; a query never compares vectors from different versions. (B) DIFFERENT dimension: ADD COLUMN embedding_next vector(NEW_DIM), backfill, build the index/ANALYZE, then in ONE migration rename embedding_next -> embedding (and old -> embedding_prev), update embedding_dim default and the CHECK; drop embedding_prev after a soak. Graphiti keeps its own name/fact embeddings in Neo4j; changing the router's embedding model therefore ALSO requires re-embedding the graph (re-save nodes/edges through the namespace API) - plan that as one 'embedding generation' change, tracked in the ledger.

### TK-01 — Tokenizer comparison and default + margin
*PASS · OFFLINE*

DEFAULT: count = ceil(max(o200k_base, cl100k_base) * 1.10), tokenizer id 'tiktoken:max(o200k_base,cl100k_base)+margin0.1' recorded in every context trace. The two vocabularies agree to within 1% on English/JSON/UUID text but cl100k_base counts ~47% MORE on multilingual text, and the router's physical model is unknown, so the larger of the two is used. A chars/4 heuristic under-counts planning_package, planning_x20, json_facts, uuid_heavy, multilingual, code_and_paths, numbers_dates and must not be used for hard budgets. The 10% margin is PROVISIONAL: TK-02 (live) measures router prompt_tokens for the same samples on each alias and raises the margin until the platform count >= the observed count for 100% of samples (after subtracting the measured per-request template overhead).

### AU-01 — Dev auth: API keys, local JWT, OIDC path
*PASS · OFFLINE*

DEV AUTH (DEC-03): platform-issued API keys (hashed with a server pepper, prefix stored and shown, constant-time compare, optional expiry, immediate revocation) bound to a workspace-scoped principal; optional 15-minute JWT from a local HS256 signer after key exchange. Library: PyJWT (small, pinned algorithms, required-claim enforcement) rather than authlib (an OAuth framework we do not need). OIDC path (documented, not built): verify RS256/ES256 via the IdP's JWKS with PyJWKClient, pin algorithms, require iss/aud/exp, and map a configured claim (or an IdP group -> workspace table) to workspace_id; the Principal shape is identical so no other code changes. Workspace ALWAYS comes from the key record/claim, never from a header or body. Sessions for the admin UI use the same JWT with kind=user.

### NW-01 — Container -> host-loopback router reachability
*PASS · OFFLINE*

VERIFIED on macOS Docker Desktop: a container reaches a service bound ONLY to the host's 127.0.0.1 through http://host.docker.internal:<port> (Docker Desktop forwards it to host loopback). The real router's unauthenticated /health was NOT tested from a container because the router was not running during this run. DEFAULTS: OSO_ROUTER_BASE_URL=http://host.docker.internal:8780/v1 for containerised api/worker in dev; http://127.0.0.1:8780/v1 for host-run processes; add `extra_hosts: ["host.docker.internal:host-gateway"]` to compose so Linux CI resolves the name. Option (b) (router on 0.0.0.0) is NOT needed and widens exposure; option (c) (api/worker on the host) is the fallback if a Docker Desktop update changes the forwarding.
